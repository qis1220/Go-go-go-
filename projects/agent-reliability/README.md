# Agent Reliability｜工具执行状态与可追溯评测

解决任务型AI助手“说已完成，但操作结果尚未确认”的问题，让用户清楚知道操作是否成功、能否继续，以及遇到异常时该如何处理。

## 目标用户与使用场景

面向构建任务型AI助手的产品和开发团队，用于验证外部工具执行时的状态与反馈规则。

典型场景：用户要求开启设备功能，系统发送指令后超时。此时操作可能已完成，也可能未完成。直接回复“已开启”会误导用户，自动重试则可能重复执行。

## 产品目标

|目标|产品行为|用户价值|
|---|---|---|
|结果可信|区分成功、明确失败和暂未确认，按实际证据反馈|用户知道是否完成，避免根据错误反馈继续操作|
|操作可控|执行前检查权限、功能支持与取消状态；同一操作避免重复发送|减少无效操作与重复执行|
|问题可查|关联消息、请求、执行步骤与结果|团队能定位失败环节，支持修复与回归|

## MVP范围与交互规则

先验证一次操作从请求到结果反馈的完整链路，采用模拟设备，无需模型API或真实硬件。

|场景|处理方式|反馈示例|
|---|---|---|
|确认成功|依据模拟设备结果确认|设备已确认开启|
|明确失败|保留失败状态|设备明确返回执行失败|
|请求超时且能核对结果|查询状态后反馈|核对成功后再告知已开启|
|请求超时且无法核对|保留未知状态，不自动重复发送|暂未确认执行结果|
|同一操作重复请求|复用已记录的结果或未知状态|返回当前状态，不重复发送|
|发送前取消或功能不支持|拦截指令|说明未发送及原因|

权限检查为模拟标志，尚未接入真实身份认证。发送后的取消与撤销不在当前范围。

## 验证方式与产品指标

当前用9个固定模拟用例检查状态、反馈和重复发送行为，结果见下文与 `results/`。

后续真实接入时重点验证：

- **操作结果反馈准确率**：与权威业务状态一致的反馈占比；无法确认时准确表述“未知”也属于正确反馈。
- **重复执行发生率**：同一业务操作被重复执行的比例，需区分传输重试与实际副作用。
- **异常处理完成情况**：失败或未知状态是否有可理解的反馈和明确的下一步。
- **确认耗时**：从用户请求到获得可信结果的耗时，分别统计正常和异常场景。

以上是待验证的产品指标，当前模拟结果不能替代真实用户或设备数据。

## 后续优先级

1. 持久化操作状态，绑定操作ID与参数，验证并发和重启后的去重。
2. 接入真实工具，核对实际状态查询与幂等能力，补充发送后取消的处理。
3. 接入模型理解与表达，分别评测意图、参数、执行和结果反馈。

## 运行

Python 3.10+，无第三方依赖：

```sh
python3 projects/agent-reliability/demo.py
```

在仓库根目录运行。产物位于本目录 `results/`，共9个用例；失败时进程非零退出。

## 执行链路

请求 → 权限 → 发送前取消检查 → 能力校验 → 幂等查询 → 工具发送 → 状态核对 → succeeded / failed / unknown → 明确反馈。

- 模型将来可负责理解表达与提出工具调用；权限、状态、去重由代码执行。本版本不接模型。
- 超时是传输现象，不是业务结论。可核对时以业务状态为准，否则保留unknown。
- message_id描述业务消息；request_id/trace_id记录执行尝试；operation_id代表同一业务操作。重试不能生成新的操作ID绕过去重。
- 轨迹使用自定义JSON结构记录步骤，尚未接入OpenTelemetry。

## 实测结果

9/9个固定模拟用例通过：正常成功、明确失败、执行成功但回执超时、超时未知、发送前取消、不支持、无权限、成功后重复、未知后重复。

验证了该程序在这些设定下的行为，不代表真实Agent成功率100%，也不证明线上业务收益。数据与期望由人设计，生成质量未被测试。

## 失败与经验闭环

模拟错误：写入后超时，旧助手却回复“已开启”。修复应先补状态契约及代码校验，再考虑Prompt和经验。见 `experience-candidate.json`，默认draft、禁止运行时发布。通过评测、审核及明确回滚版本后才考虑启用。

后续闭环：轨迹 → 清洗/去重 → 规则与人工检查 → 标注 → 版本化案例集 → 经验假设 → 审核 → 保留集回归。当前只实现模拟轨迹与规则评测，清洗、标注平台、经验检索、MCP发布尚未实现。

## 已知局限

- 内存去重不跨进程、非并发安全；生产需要持久化、原子约束和业务端幂等。
- 同一operation_id要求上游绑定同一操作内容；生产还需验证参数指纹，防止ID复用到不同指令。
- 仅验证发送前取消；发送后取消不保证撤销已执行动作，必须单独查询和设计补偿。
- unknown可能代表动作已执行，也可能未执行。本模拟“不明确状态”没有真实外部环境，不能验证物理状态。
- 明确失败后的人工重试与新操作ID策略未实现。
- 无身份系统、输入Schema、敏感日志治理或网络接口，不作为可部署控制服务。
